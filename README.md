# 瓷韵｜中国陶瓷数字文化体验微信小程序

面向数字媒体设计比赛的中国陶瓷文化体验项目，以“赏瓷、识瓷、问瓷、制瓷、闯关”串联文化学习与数字创作。前端采用微信原生小程序，云端使用腾讯云 CloudBase。

## 功能入口

| 页面 | 当前功能 |
| --- | --- |
| 首页 | 文化内容推荐、视频课堂、陶瓷资讯及核心体验入口 |
| 瓷馆 | 按朝代筛选、关键词搜索、器物详情、相关视频与 AI 文化问答 |
| 工坊 | 数字制瓷、AI 创瓷、最近创作、作品预览与删除 |
| 挑战 | 三章十二关、五种玩法、通关素材奖励与章节徽章 |
| 我的 | 根据实际行为累计的成长等级、探索足迹、六枚成长徽章与成长日志 |

识瓷支持拍照或相册选图，展示器型、纹饰、釉色、工艺和文化解读，并提供本机识别历史。识瓷用于文化观察，不作为年代、真伪或价值鉴定。

AI 创瓷支持青花、粉彩、单色釉、水墨写意、仿古五种风格，包含实时生成、任务恢复、大图预览和作品管理。精选案例有明确来源标记；内置 imagegen 展示图不算作本次实时 Seedream 结果。

数字制瓷按器型、纹样、釉色分步创作，支持自动保存草稿和作品命名。六种器型均支持六种纹样与六种釉色的完整组合预览，共 216 种组合。

## 挑战与成长

十二关分为“溪畔识瓷、青花作坊、窑火成器”三章，每章四关。

| 玩法 | 关卡 |
| --- | --- |
| 纹样消消乐 | 1、6、11 |
| 瓷纹连连看 | 2、9 |
| 古瓷拼图 | 3、7、12 |
| 瓷器辨形 | 4、8 |
| 瓷识小问答 | 5、10 |

当前 `data/challenge-settings.js` 的 `freeAccess: true` 为开发演示开放全部关卡；改为 `false` 可恢复顺序解锁。通关仍须完成真实游戏目标，进入关卡、查看原图或使用提示不会自动完成。

真实通关会保存进度并解锁对应器型、纹样或釉色；每章四关全部完成才获得该章徽章。地图星星仅作展示，不参与评分、游戏参数或解锁。重玩不重复发放奖励和成长经验。

“我的”使用本机成长账本，不是固定示例资料。每日探索、浏览不同馆藏、有效识瓷、完成问答、保存本人作品和通关均可积累成长值，同一事件按标识去重；展示案例不计入本人创作成长。

- 成长等级共七级，成长值门槛为 0、50、150、300、500、800、1200。
- 匠心巧手：保存 10 件本人数字作品；灵感造物师：保存 5 件本人真实 AI 作品。
- 慧眼识珍：完成 20 次有效识瓷；博古知瓷：浏览 10 件不同馆藏；问瓷求真：完成 30 轮问答。
- 瓷境宗师徽章：上述五项全部达成，同时成长值达到 1200、实际探索 14 天。

成长徽章与挑战章节徽章使用不同条件，分别在“我的”和挑战成就中展示。具体成长规则在 `data/growth.js`。

## 在微信开发者工具中运行

1. 安装微信开发者工具，登录拥有项目权限的微信账号。
2. 选择“导入项目”，目录选择本 README 所在的项目根目录。
3. 使用已获授权的 AppID；当前项目配置不代表任意微信账号都拥有权限。
4. 检查 `app.js` 的云环境、`cloudbaserc.json` 的部署环境及静态素材配置是否对应同一套资源。
5. 点击“编译”；需要手机预览时重新生成开发预览码，并检查图片、视频、相机授权及 AI 完整流程。

迁移到自己的 AppID / 云环境时，需要更新项目配置、云函数、数据库与索引、私有存储、视频目录中的文件 ID，以及静态素材域名。仅修改 AppID 不能复用原项目的云资源权限。

## 云服务与 AI 部署

项目包含三个云函数：

| 云函数 | 用途 |
| --- | --- |
| `ciyun-ai` | 文化问答、图片识瓷、创瓷任务接口、私有资源签名与本人 AI 作品管理 |
| `ciyun-image-worker` | 领取队列中的创瓷任务，调用 Seedream 并转存生成图片 |
| `video-playback` | 根据固定视频目录返回临时播放地址 |

`server/ai/` 是两个 AI 云函数的规范源码，`npm run build:ai` 将其复制到 `cloudfunctions/ciyun-ai/` 和 `cloudfunctions/ciyun-image-worker/`。源码与可部署函数包都应保留；修改后端后先构建再部署。

当前云函数配置使用 Nodejs20.19，AI 包依赖 `wx-server-sdk@4.0.2`，部署时安装函数依赖。文化问答与识瓷使用 DeepSeek，实时创瓷使用火山方舟 Seedream。

云端环境变量包括 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`ARK_API_KEY`、`IMAGE_MODEL`、可选的 `IMAGE_SIZE`。worker 使用约每 10 秒运行的定时触发器，空队列不调用模型；禁止客户端直接调用 worker。

模型密钥只配置在云端环境变量中，不写入小程序、Git、文档或公开静态目录。数据库和私有图片应由服务端校验当前身份后访问。

环境配置、权限与定向部署命令见 [AI 部署指南](docs/AI-DEPLOYMENT.md)。修改 AI 时只部署指定函数，避免覆盖已有视频服务。

## 图片资源与小程序打包

较大的馆藏、工坊、封面和精选案例图通过 CloudBase 静态托管 HTTPS 加载；`utils/static-media-manifest.js` 是微信运行时映射，`.json` 为配套元数据。`app.js` 初始化后启用映射，数据源仍保留稳定的原始路径。

`project.config.json` 的打包排除项与 manifest 共同控制包体。清单的 `files` 对应当前维护素材，`legacyFiles` 保留旧记录路径的远程兼容映射；运行时解析两者的并集。旧本地副本可移出项目，CDN 中的兼容资源仍需保留。更换托管时需同步上传资源、更新映射并配置微信合法域名。

导航图标、必要背景、成长与章节徽章、游戏图片等仍需要代码实际引用的本地 PNG/JPG。未使用的 WebP、旧素材副本和可再生导出已移出项目；不能据此删除手机包仍依赖的 PNG/JPG，也不能仅凭开发者工具中可见便判断手机兼容。

`design-assets/` 保留当前器型与釉色制作的输入、图层、构建脚本及 manifest。大尺寸釉色母版可按目录说明重新生成，运行素材与制作工具分别维护。

主包和 `games/` 分包应分别检查大小。自动测试、项目校验与离线编译不能替代微信真机视觉、触摸、网络与权限验收。

## 数据保存边界

- 本机保存：数字制瓷草稿与作品、收藏的展示案例、识瓷历史、聊天归档、挑战进度、解锁素材及成长记录。
- 云端保存：AI 任务、私有图片与本人实时生成历史。作品页可重新读取当前微信身份的成功 AI 作品，包括未手动收藏的成功记录。
- AI 专属作品入口只展示本人实时生成记录；工坊综合作品列表合并数字作品、AI 作品与收藏案例。
- 删除真实 AI 作品会在云端标记隐藏并移除本机收藏，保留任务与私有资产；删除数字作品或展示案例只影响本机记录。

清理微信缓存或更换设备会影响本机数据，项目不提供数字作品、聊天、挑战及成长记录的跨设备同步。私有图片通过稳定资源标识重新签名，临时 URL 不作为永久地址。

## 开发与校验

本地脚本使用 Node.js，建议与云端保持 Node 20 或更新版本。根目录没有 npm 依赖，运行以下命令无需先执行根目录 `npm install`：

```powershell
npm test
npm run build:ai
npm run validate
```

`npm test` 运行 Node 内置测试；`npm run test:ai` 可运行 AI 相关测试。`validate` 检查页面、Tab、基础组件及部分数据引用，不代表云环境已经部署或模型调用成功。
